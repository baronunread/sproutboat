# Component inventory

The full list of components `@sproutboat/ikada` needs. It starts from the index at <https://kumo-ui.com/llms.txt>, used only as a checklist of what a product UI covers, and adds the Sproutboat-specific pieces. Nothing here copies another library's look, wording or code.

Priority: **P0** is built in phase 1, **P1** is next (needed by the dashboards' first screens), **P2** comes later. "Base UI" names the primitive from `@base-ui/react`; "none" means plain elements.

Common states for every interactive component: rest, hover, focus-visible, active, disabled, plus the ones listed per row. All components take `className` and `ref`, use logical properties, and honour reduced motion (see `DESIGN.md`).

## Phase 1 scope

P0 rows are built, tested and shown in the playground. The dashboard essentials batch (Sidebar, PageHeader, Breadcrumbs, Spinner, Banner, Table, EmptyState, Meter, UsageMeter, MetricTile, CommandPalette, plus the small Kbd keycap) is built too, tested with axe-core, and composed in the playground's Dashboard preview. The app batch for the Community dashboard (the router link adapter on Link, SidebarItem, PageTab and Breadcrumbs, Avatar, SegmentedControl, RadioGroup, SensitiveInput, DescriptionList, Pagination, CodeBlock) is built, tested with axe-core and shown in the playground's "Account and app pieces" section. Components that only the Cloud product needs (runtime chips, fallback pills, traffic splits, canary phases in the deploy toast) do not live in this open package. Everything marked `todo` keeps its row here so the API vocabulary (`tone`, `status`, `label`, `size`, `variant`) stays consistent when it lands.

There is no notification bell: events live on an Activity page (the Activity feed row, P1), reached from the Sidebar.
